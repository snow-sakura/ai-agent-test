# 需求文档 · 生成可靠性修复 + 序列调度 + 纯 GitHub 演示

> 版本：2026-10 迭代 · 状态：已实现并通过浏览器实测验收

## 1. 背景与痛点

平台接入真实 AI 模型（AMD GPU Cloud 免费模型，推理约 50 字/s）后暴露四类问题：

| # | 痛点 | 现象 |
|---|------|------|
| R1 | 生成"不是失败就是缺失" | 慢速模型流式响应中途停滞，前端永远转圈，无终止帧 |
| R2 | 输出截断无补救 | `max_tokens` 无上限或截断后原始 JSON 直接解析失败 |
| R3 | 批量任务互相干扰 | 多任务同时打免费模型，额度限流导致整批失败 |
| R4 | 无批量视图 | 多份需求只能逐个生成，看不到整体进度 |

## 2. 目标用户与场景

- **测试工程师个人**：免费额度下批量生成用例，要求"跑着不管也不会全军覆没"。
- **付费团队**：多需求并发生成，要求吞吐随并发线性提升、可看进度可重试。
- **演示/评审**：零部署在 GitHub Pages 上完整展示调度策略差异。

## 3. 功能需求

### F1 生成结果修复（缺陷）
- A1 所有 AI 流式接口服务端停滞看门狗：75s 无数据即终止，必有终止帧（done/error）。
- A2 统一 `max_tokens=4096`，捕获 `finish_reason=length` 并明示截断。
- A3 截断输出自动修复：尽力解析出结构化用例，标注"已自动修复"。
- A4 空流/异常统一转 error 终止帧，不再静默。
- A5 非流式统一 timeout 180s。
- A6 前端 120s 停滞看门狗（AbortController）；缺 done 帧时明示并保留已生成内容。

### F2 生成序列调度（新能力）
- B1 模型计费档位 `tier ∈ {free, paid}`，配置中心可编辑，全站生效。
- B2 调度决策：free → `serial/并发1`（按提交顺序串行）；paid → `parallel/默认3`（可配 1-8）。
- B3 序列生命周期：提交 → 排队 → 执行 → 完成/部分失败/全部失败；支持取消、只重试失败任务。
- B4 提交前调度预览：选模型+任务数即返回策略、并发数、预计墙钟。
- B5 进程重启：遗留"执行中"自动置"已中断"，可重试。
- B6 单序列 ≤ 20 任务；任务失败互不影响。

### F3 前端显示优化
- C1 用例工作台「序列生成」页签：每行一任务的任务清单、模型下拉（🆓/💎 徽标）、
  调度预览徽标、付费并发步进器。
- C2 序列实时时间线：序号任务 chip（⏳/🔄/✅/❌/⊘）、总进度条、状态色；2s 轮询。
- C3 操作：取消、重试失败、结果一键载入用例表（跨任务合并编号）。
- C4 配置中心「计费档位」下拉，保存即同步 ai_configs 与调度。

### F4 演示与交付
- D1 `demo/` 纯 GitHub Pages 静态演示（无后端）：模拟串/并调度 + 时间线 + 记录数据。
- D2 文档四件套：需求 / 技术 / 操作说明 / README 全流程（截图实测）。
- D3 仓库无密钥、无构建产物、无垃圾文件。

## 4. 非功能需求

- 可靠性：任何 AI 调用在 180s 内必有明确结局（成功/失败/截断），不允许无限挂起。
- 兼容性：匿名可用（created_by=guest），登录后可区分归属；无 Key 走演示模式体验完整。
- 性能：并行只面向 paid；free 严格串行防止额度被限流。

| 项 | 现象 | 结论 |
|----|------|------|
| B3 取消 → 重试 | 取消后 `fail_cnt` 未回写，「重试失败任务」按钮不显示 | ✅ 已修复并实测 |
| B5 重启 → 重试 | 「已中断」只改序列状态，任务项/计数未归一，重试实为无效操作 | ✅ 已修复并实测 |
